# server -- /lfs-audit, 2026-09-21

Native (booted 13.1 root on sdb2, uptime 15 min at scan start). Kernel
7.1.8-lfs-13.1-systemd, NVIDIA 470.256.02, glib 2.88.3, gobject-introspection
1.86.0. First audit for this host; no prior report to diff against (laptop has
2026-09-03 and 2026-09-05).

## Critical

- **FIXED. awesome cannot start: lgi 0.9.2 vs current GLib.** `lgi/ffi.lua`'s
  `load_enum()` calls `core.record.fromarray(enum_class.values, i)`. GLib 2.88.3
  annotates `GEnumClass.values` / `GFlagsClass.values` as
  `(array length=n_values)` in `GObject-2.0.gir`, so lgi marshals the field into
  a 1-based Lua table of records and `fromarray()` raises
  `bad argument #1 to 'fromarray' (lgi.record expected, got table)`.
  `lgi/override/cairo.lua` is the first caller (26 enums at require time), so the
  whole cairo binding dies and awesome follows with
  `gears/color.lua:132: attempt to call a nil value (field 'create_rgba')`,
  then `couldn't find any rc file`, then exit. Reproduced under Xvfb; fixed and
  verified with a patched copy on LUA_PATH (awesome stayed up, silent, 2+ min).
  Recorded in `recipes/blfs-lua-lgi.sh` as patch (2).
  Xorg itself is fine -- `/var/log/Xorg.0.log` shows the NVIDIA driver binding
  DFP-1 (Acer V193W, 1440x900) and the server exiting 0 when awesome quits.

## Worth doing

- **FIXED. GRUB `search --set=root --fs-uuid 4ed155bc-b1da-4117-9f92-9c952e807880`
  matches no filesystem on this machine** (sdb2 is `cb1db9c1-...`, sda2 is
  `ca21e228-...`). It boots only because a failed `search` leaves `$root` at the
  device GRUB loaded from. Stale UUID carried through the re-image, in both
  `/boot/grub/grub.cfg` and `hosts/server/overlay/boot/grub.cfg`.
- ~~`root=PARTUUID=c2cd0612-02` on the kernel command line contradicts the
  by-LABEL convention.~~ **Retracted.** There is no initramfs on this system, and
  the kernel's `name_to_dev_t` resolves `PARTUUID=`/`PARTLABEL=`/a `/dev` node
  only -- a *filesystem* label needs udev, i.e. an initramfs. `BOOTSTRAP.md:143`
  already documents this and says so explicitly. The PARTUUID form is correct and
  was left alone. The by-LABEL convention applies to `/etc/fstab`, which follows
  it, and now to GRUB's own `search`, which can read ext4 at that stage.
- **FIXED. `bin/lfsmaint` hardcoded `BOOK_RELEASE = "13.0"` (line 47)** while this host
  pins 13.1 in `host.toml [books]`. `lfsmaint report` prints `book release: 13.0`
  and `lfsmaint advisories` queries the 13.0 advisory feed for a 13.1 system --
  wrong security data, cached as `advisories-13.0.json`. Should come from
  `bin/lfshost.py`, like every other host fact.
- **FIXED. `lfsmaint advisories` could not run as john**: `PermissionError` writing
  `/var/lib/lfsmaint/advisories-13.0.json`. Needs root, or a fallback cache path.
  Advisory coverage is therefore unchecked this run.
- **FIXED. `lfsmaint verify`: 14 unexplained missing files across 5 packages**
  (112 others accounted for by ch08-cleanup pruning):
  dbus-1.16.2 (8, all under `/usr/share/doc/dbus`),
  nvidia-470xx (`/var/lib/nvidia/dirs`, `/var/lib/nvidia/log`),
  openbao-2.6.2 (`/root/go/bin/bao`), pulseaudio-17.0
  (`/etc/xdg/autostart/pulseaudio.desktop`,
  `/etc/xdg/Xwayland-session.d/00-pulseaudio-x11`),
  sudo-1.9.17p2 (`/etc/sudoers.d/00-sudo`). The sudo one is the only config-tree
  entry and the only one worth chasing.
- **CLOSED, no action. `vmscape: Vulnerable`** in `/sys/devices/system/cpu/vulnerabilities/`, with no
  mitigation offered by kernel 7.1.8 on this Sandy Bridge part. Microcode is
  current (`0x2f`, `old_microcode: Not affected`), so this is a kernel-side gap,
  not the missing-initrd case laptop hit.
- **FIXED. awesome installed its system default config to `/usr/etc/xdg/awesome/rc.lua`**
  -- `CMAKE_INSTALL_PREFIX=/usr` with SYSCONFDIR left at `${prefix}/etc`. Non-FHS,
  and the path awesome falls back to when a user has no `~/.config/awesome/rc.lua`.
  `recipes/blfs-awesome.sh` should pass `-D SYSCONFDIR=/etc`.
- **FIXED. `findmnt --verify`: `/dev/pts` specified before `/dev` in `/etc/fstab`.**
  One real error, everything else clean.

## Disposition

Every finding above was acted on the same day. Repo-side changes are committed;
the live-system half is `apply-audit-fixes.sh` (lgi patch, awesome config path,
grub.cfg, fstab, database rebuild, strip+gzip), which needs root and is
idempotent. `host.toml`'s stale `kernel = "6.18.10"` was corrected to `7.1.8` and
is not listed above because it was already on the previous BUILD-REPORT entry's
own step-6 list.

Two findings close without a change, with the reasoning recorded in
`hosts/server/kernel-config.sh` next to the options they concern: the Broadcom
BCM4321 stays unbound, and `vmscape` has no mitigation to enable on a kernel with
`# CONFIG_KVM is not set`.

One finding was wrong and is struck through above rather than deleted.
